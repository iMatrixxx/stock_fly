## 4b. 更正记录：① 二次确认"不用再改代码"是错的

原文（上表 ① 行）写"预筛与主链集成已完成，无论选哪条都不用再改代码"。**对 ③（开白名单）
成立，对 ②（报告 LLM 确认）不成立**，原因是**时序**：

`industry_intel` 在 `fetch_market` **步骤 10** 就被冻结进 `market_<date>.json`，而 LLM
写报告在证据链**之后**。若"确认"与"写报告"同一时刻发生，当天证据链早已读完
`events/<date>.jsonl`——确认结果**当天读不到**，报告第 1 段照旧是空的。
"已经在环内"不等于"在正确的时点上"。

正确形态 = 把确认**前移**到证据链之前，成为独立一环 **④.55**（夹在 ④.5 预筛与
④.6 验证建库之间），并定义**输出契约**（裁定包 → 裁定书）：

- 裁定包 `outputs/<date>/confirm_packet.md`：自带候选明细 + 生效规则 + 正反样例 +
  JSON 契约，不依赖对话上下文；
- 裁定书 `outputs/<date>/confirm_decisions.json`：逐条 confirm/reject + 理由，
  **与候选池分开存放**（候选池每天被覆盖重建、confirm 被重置；裁定书是幂等的那一份）。

代价是主链多一步、且当日流程变成"先出包 → 裁定 → 再跑主链"（或主链跑完补裁定后以
`--refresh` 重取，**仅限当日**）。这是为了让第 1 段真的有数据而必须付的代价；
不想要这一步时用 `--no-confirm` 跳过，第 1 段回到"无已确认产业事件流"的诚实状态。

## 5. 修订过程中新发现并已修的问题

### 5.1 公告源整体绕过噪声词典（结构性漏洞）

`noise_rule()` 的第一行是 `if (extra or {}).get("code"): return None` —— **凡公告源（自带 code）
直接放行，不进任何噪声规则**。原前提"公告有主体、一定相关"对**产业事件**不成立：公告标题的
关键词匹配有大量定式误报，「未来三年股东回报规划」命中 policy 的`规划`、公司名「电投产融」
命中 capacity_expansion 的`投产`。

这是"豁免规则随使用方式变化而过期"的典型：code 豁免当年是为防误剔设的，一旦开始**按标题关键词
抽事件**，它就变成了"防正确剔除"。修法：新增 `noise_filter.json` 的 `announcement_noise` 定式词表，
并让它**先于 code 豁免**生效（`noise_rule` 加 `ann_phrases` 参数，默认空以保持向后兼容）。

### 5.2 `promote` 会静默清空已确认的事件流（数据丢失）

`promote()` 原先无条件覆盖输出文件。主链每天重跑预筛会把候选池整体重置为 `confirm=false`
（`generate` 是覆盖写），于是**前一天人工确认攒下的事件会在第二天被清空**——不报错、不留痕。
修法：无确认候选时不写文件、保留已有内容，并打印 `[INFO] 无新确认候选 → 保留已有 …`。
已加测试 `test_promote_without_any_confirmed_does_not_wipe_existing`。

### 5.3 附带：一个定时炸弹测试

`tests/test_index_degradation.py` 把日期**写死**成 `2026-09-11`，而 `_patch_index_close_from_tencent`
有"距今 ≤5 个自然日"的窗口守卫——09-17 起该测试**必然失败**（与代码改动无关，是测试自己写死了
绝对日期）。已改为相对今天构造，与同目录 `test_live_date_guard.py` 对齐。

### 5.4 一次被实测否掉的"自动确认"（决策记录）

修复①时先实现了最直觉的规则：`auto_confirm_via=["extra_code"]`——"公告记录自带 `code`，
说明有明确主体，可自动确认"。并真的对 09-14/15/16 跑了 `--auto`，产出 3 条事件流。

**随后实测否决，理由三条**：

1. **不可用**：15 条 extra_code 候选里 **0 条**落在 `chains/*.json` 映射表内（当时只有 `ai_compute`，约 30 只）
   ——自动晋级出来的"产业情报"没有任何链上的下游消费者。
2. **不可信**：内容以治理类定式为主（股东回报规划／董事会决议／保荐代表人变更／工商变更登记／
   市场传闻澄清…），本身不含任何产业信息。
3. **匹配机制会放大它**：公司名「电投产融」直接命中 `capacity_expansion` 的`投产`。

→ `events/signals.json` 的 `auto_confirm_via` **回滚为 `[]`**，3 条垃圾事件流从 `events/` 移除
（暂存 `/tmp/stock_rejected_auto_intel/`），候选池重生成（全部 `confirm=false` 待人工）；
否决理由原文写进 `auto_confirm_rejected_extra_code`，避免下次再想当然。

这也是 §5.1 那个公告源噪声漏洞**被发现的契机**：正是把公告源自动晋级之后，"公告完全绕过噪声词典"
才从一条看不见的死代码变成会污染证据链的现实问题。**先接通再验证，比先论证再接通更能暴露结构性缺陷。**
