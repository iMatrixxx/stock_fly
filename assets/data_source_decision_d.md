# ④ 订单验证 · 公开源定源决策（实测日 2026-09-17）

> 用户拍板：**公开源**。本文是"先定源"的交付物——把候选公开源**逐个打真请求**，
> 用实测结果决定用谁、不用谁、以及各自的契约与坑。所有结论都有可复现的命令与返回。
>
> 判定标准（四条缺一不可）：
> 1. **可达**（不挂代理、不依赖境外节点）；
> 2. **结构化**（返回 JSON / 可解析文本，不是 JS 壳）；
> 3. **可消费**（含日期与数值字段，能构成序列或账本）；
> 4. **可回溯**（能取到指定历史日期，否则无法核对已发生的事件）。

## 1. 采用源 A：新浪期货主连日K（价格序列）

**端点**
```
https://stock.finance.sina.com.cn/futures/api/jsonp.php/var%20t=/InnerFuturesNewService.getDailyKLine?symbol=<CODE>0
```
镜像域名 `stock2.finance.sina.com.cn` 同样可用（实测两者返回一致）。

**契约**
- `symbol` = 品种码 + `0`（主力连续），如 `LC0`（碳酸锂）、`PS0`（多晶硅）、`CU0`（铜）。
- 返回 **JSONP**：`/*<script>...</script>*/\nvar t=([{...},...]);`，需 `index("([")` / `rindex("])")` 截取。
- 字段：`d` 日期 / `o` 开 / `h` 高 / `l` 低 / `c` 收 / `v` 量 / `p` 额 / `s` 结算。
- 单请求返回**上市以来全部日K**，约 0.3 MB，**不需要分页**。

**实测覆盖（2026-09-17 探测 56 个品种，56/56 全部可用）**

| 板块 | 品种（代码） |
|---|---|
| 贵金属 | 黄金 AU0、白银 AG0 |
| 有色 | 铜 CU0、铝 AL0、锌 ZN0、铅 PB0、镍 NI0、锡 SN0、氧化铝 AO0、国际铜 BC0、不锈钢 SS0 |
| 新能源/硅 | **碳酸锂 LC0**、**工业硅 SI0**、**多晶硅 PS0** |
| 黑色 | 螺纹钢 RB0、热卷 HC0、铁矿石 I0、焦炭 J0、焦煤 JM0、硅铁 SF0、锰硅 SM0 |
| 能源/航运 | 原油 SC0、燃料油 FU0、沥青 BU0、液化石油气 PG0、集运欧线 EC0 |
| 化工 | PTA TA0、对二甲苯 PX0、甲醇 MA0、聚丙烯 PP0、塑料 L0、PVC V0、乙二醇 EG0、纯碱 SA0、烧碱 SH0、尿素 UR0、短纤 PF0、苯乙烯 EB0、瓶片 PR0、丁二烯橡胶 BR0 |
| 农产品 | 豆粕 M0、豆油 Y0、棕榈油 P0、菜油 OI0、菜粕 RM0、豆一 A0、玉米 C0、淀粉 CS0、棉花 CF0、白糖 SR0、苹果 AP0、生猪 LH0、鸡蛋 JD0、橡胶 RU0、20号胶 NR0、纸浆 SP0 |

历史长度样本：`CU0` 5281 根（2005-01-04 起）、`LC0` 767 根（2023-07-21 起）、`PS0` 419 根（2024-12-26 起）。
**全部品种末行 = 2026-09-16（最近交易日）**，说明序列每日更新可用。

**⚠️ 边界（写报告必守）**
- 仅支持**国内商品期货**。美元指数、离岸人民币、COMEX/CBOT 外盘商品**无稳定公开历史源**
  （东财 `push2his` 有 IP 级风控、新浪相关 service 已下线）→ 报告中禁止编造美元/外盘数值。
- 交易日 T 的日K = **T 当日日盘 + T-1 夜盘**（A股 T 日盘中全程可感，视为当日同步催化）。
- 品种上市日之前无数据：`PS0`（多晶硅）只有 2024-12-26 之后，**核对 2024 年以前的硅料事件会无数据**——
  此时必须报 `no_data`，不得用 `SI0` 代偿。

## 3. 采用源 B：巨潮资讯公告全文检索（订单/扩产账本）

**端点**
```
POST http://www.cninfo.com.cn/new/hisAnnouncement/query
Content-Type: application/x-www-form-urlencoded
Referer: http://www.cninfo.com.cn/new/commonUrl?url=disclosure/list/notice
```

**参数**：`pageNum` / `pageSize` / `column=szse` / `tabName=fulltext` / `searchkey=<关键词>` /
`seDate=<起>~<止>`（闭区间）/ `isHLtitle=true`。

### 🔴 最重要的坑：编码方式决定成败，且**失败时不报错**

同一个请求体，两种编码，结果完全不同：

| 编码 | `totalAnnouncement` | 返回内容 |
|---|---|---|
| `application/json` | **530392**（与实际无关） | 不受关键词/日期约束的**全量公告流**，首条是"为参股公司提供担保的公告" |
| `application/x-www-form-urlencoded` | **4**（正确） | 2026-09-14~09-17 且标题含「中标」的 4 条：金智科技 / 山科智能 / 蒙草生态 / 交投生态 |

JSON 编码下服务端返回 **HTTP 200 + 结构完整 + `hasMore=true`**，只是**静默忽略 `searchkey` 与
`seDate`**。这正是本项目最防的一类错（不报错、不缺字段、内容全错）。故 `data/cninfo.py` 里
专门用 `net.post_form` 而非 `post_json`，并在 docstring 里写明"不要改成 JSON"。

**其他实测契约**
- `column=szse` **同时返回沪深两市**（沪市 601899 紫金矿业亦在结果内），故作为统一取值。
- 分页有效且单调：`pageNum=1/2` 各返回 30 条。
- 可回溯：单日检索 T-1 / T-3 / T-7 / T-14 / T-30 / T-60 / T-120 / **T-250** 全部有返回。
- 单篇全文可取：`static.cninfo.com.cn/<adjunctUrl>` 返回 `%PDF-1.7`（117 KB）。
- **`secName` 与标题都带 `<em>` 高亮**（实测 `电<em>投产</em>融`）→ 两者都必须剥离，
  只清洗标题会让主体名匹配静默失效。
- `announcementTime` 是**毫秒**时间戳，按 Asia/Shanghai 解码。
- 已知噪声：检索是**全文**匹配，公司名本身可能含检索词（「电投产融」命中`投产`），
  故账本会混入与订单无关的记录。账本只做"按代码/主体定位后查在不在"，不做计数判断，
  噪声只增体量、不改判定。

## 4. 采用源 C：巨潮主体解析（定位核对对象）

```
POST http://www.cninfo.com.cn/new/information/topSearch/query
Content-Type: application/x-www-form-urlencoded   # 同样是 form
keyWord=<公司简称>&maxNum=10
```
返回 `[{"code":"000969","zwjc":"安泰科技","pinyin":"atkj","orgId":"gssz0000969",...}]`。
实测：安泰科技→000969、耐科装备→688419、欧菲光→002456、云南锗业→002428、金智科技→002090、博敏电子→603936。

**为什么需要它**：事件流里大量"公司公告"被预筛归成 **node/industry 粒度**（文本带公司名、
但结构化 `target` 为空）。不定位主体，这些事件的公告核对只能一律标 `no_data`，
而实际上"核对对象明确、账本里没有它"应当是 `not_confirmed`——两者语义不同
（无数据 vs 证据未跟上），报告措辞也完全不同。

## 5. 落盘策略（为什么两类数据一个有库、一个没有）

| 数据 | 是否落盘 | 原因 |
|---|---|---|
| 期货序列 | ❌ 不落盘，只用 `data_cache` TTL 缓存 | **可重建**：新浪任何时候都能取回同一段历史 |
| 公告账本 | ✅ `hithink_out/raw/cninfo/<date>.jsonl` | **不可重建**：巨潮检索是**实时**接口，"中标"类公告日后会被挤出检索窗口/分页深度，隔几天再查同一区间条数与内容都可能不同。必须冻结"事件当日那份账本"，否则是拿今天的信息核对昨天的结论（未来函数） |

账本窗口 = `[复盘日-1, 复盘日+1]`（对称）：公告可能**早于**事件（先公告、后被转成新闻）
或**晚于**事件（新闻先出、次日才披露），单边窗口会漏。

**回填注意**：对历史日回填的账本反映的是"今天能查到的那段历史"，与当日真实可见的账本
可能有差异（这正是要落盘的原因）。回填账本只用于**事后复盘**，不得用来回溯修改历史结论。

## 7. 仍未解决的（诚实清单）

1. **现货价 vs 期货价的口径差**：期货主连是"预期价 + 持仓结构"的合成，与现货报价不完全同向。
   验证器只能回答"该品种的期货市场同步/未同步"，**不能等同于"该公司的产品真的涨价了"**。
   故判定用 `not_confirmed`（证据未跟上）而非"证伪"，并在 `basis` 里写明口径。
2. **无价格验证源的环节**：`storage`（存储/HBM）与 `optical`（光模块）无对应商品期货
   （前者寡头协议定价、后者定制工业件）。这两个环节的涨价/缺货事件永远只能 `no_data`，
   已写进 `events/commodity_map.json` 的 `excluded`，报告必须明示"无验证源"。
3. **`upstream` 强度只能印证成本端**：铜之于 PCB、工业硅之于芯片，是上游原料而非该环节产品。
   报告禁止据此断言该环节产品涨价。
4. **招投标一手数据未接入**：真实订单规模（中标金额、采购方）在招投标平台，目前只能靠
   巨潮公告标题这一层。若日后需更强的订单证据，需另找可结构化的招投标源。
5. **巨潮检索的实时性**意味着账本质量依赖抓取时点；若某日漏建库，该日订单侧永久只能 `no_data`。
